# Audit: cursor-kiro-copilot-generators

> Compliance-tracking scaffold. All rows are seeded `PENDING`; the `sdd-auditor` fills in
> status and evidence after implementation. Traceability is reflexive: every `Rn` cites an
> `intent.md` goal (`Gn`) or success criterion, every `Cn` cites a `contract.md` interface,
> mapping table or numbered Behavior Guarantee, and every `Tn` cites the guarantee or
> error-handling row it verifies.
>
> **Standing instructions carried into this audit** (from `specs/cli-skeleton/audit.md`,
> both passes — they are not optional here):
> 1. **Run the toolchain yourself.** `npx tsc --noEmit`, `npm run build`, `npx vitest run`,
>    `npm pack --dry-run`, `git status --porcelain -- templates .claude`. Do not accept a
>    reported pass. Confirm zero `.skip`/`.todo`/`.only`.
> 2. **`npm test` does not build** (AL-20). Any end-to-end assertion is against whatever
>    was last built into `dist/`. Rebuild before trusting one, and say so in the evidence.
> 3. **Verify fidelity non-self-referentially** (AL-6, AL-23): slice canonical bodies out
>    of the raw `templates/*.md` files with `fs.readFile`, never through
>    `parseRoleTemplate`/`parseConductorTemplate`, and assert against freshly generated
>    output.
> 4. **Mutation-test the new tests** (AL-21): break the behavior each one guards in `src/`,
>    confirm it fails, restore. Three of `cli-skeleton`'s shipped defects survived a green
>    suite.
> 5. **Watch for a test whose name overstates its coverage** (AL-19) — especially the three
>    tests re-pointed from `cursor` to `codex` in Phase 3.3.
> 6. **The per-tool facts are the substance of this feature.** Spot-check at least one
>    pinned value per tool against the vendor's live documentation and record what you
>    checked; a generator that writes to a path the tool never reads fails silently with
>    exit code 0.
